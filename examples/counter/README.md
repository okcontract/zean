# Verify a saturating counter

Start with a byte counter that adds one up to 255. Then change the step to two
and use the proof to catch a missed change to the guard.

```sh
zig build counter-run
zig build counter
```

`counter-run` prints the working Zig results. `counter` tests every byte
input, checks source hashes and Lean proofs, and requires the stale contract
and overflowing edit to fail. It also tests 4,608 boundary and sampled
`u32` inputs. Both targets use retained captures where needed.

## Prove the first version

```zig
pub export fn advance(value: u8) u8 {
    return if (value < 255) value + 1 else 255;
}
```

The native tests compute the reference in a wider integer. The independent
Lean specification is `min (x + step) 255`. The generated `fn_advance`
retains the guard, unchecked addition from ReleaseFast AIR, and result.
[Zig function](v1/counter.zig) · [Specification](../../lean/Compiler/Tutorial/Counter/Spec.lean) ·
[Generated model](../../lean/Compiler/Tutorial/Counter/V1/Generated.lean)

`advance_correct` proves an `.ok` result for every `0 ≤ x < 256`. Split on
`x < 255`. On the addition path, `omega` proves that `x + 1` fits in a byte.
The other branch returns 255. `advance_safe` adds the bounds
`x ≤ result ≤ 255`. Use `zig build counter-proofs` to check the proofs.
[First proof](../../lean/Compiler/Tutorial/Counter/V1/Proofs.lean)

## Change the step

With `value + 2` and the old guard, input 254 reaches the addition and
overflows. The checked model returns `.error .illegalBehavior`.
`zig build counter-broken-proof` requires Lean to reject the claim that this
input succeeds. The counterexample executes in Lean.
[Broken Zig](broken/counter.zig) · [Overflow witness](../../lean/Compiler/Tutorial/Counter/Broken/Proofs.lean) ·
[False proof](BrokenProof.lean)

Lower the guard to `value < 254`. Change the exact specification to
`Spec.advance 2 x` and prove `x + 2 < 256` on the addition path. The shared
bounds theorem still applies. `zig build counter-stale-proof` rejects the
old contract at input 0, where the new function returns 2.
[Repaired Zig](v2/counter.zig) · [Updated proof](../../lean/Compiler/Tutorial/Counter/V2/Proofs.lean) ·
[Comparison theorem](../../lean/Compiler/Tutorial/Counter/Comparison.lean)

The `u32` version guards addition at `x < 4294967294`. The same reasoning
proves successful saturation and the bounds for all 2³² inputs.
[Wide Zig](u32/counter.zig) · [Wide proof](../../lean/Compiler/Tutorial/Counter/Wide/Proofs.lean)

## Regenerate and replay

Use an instrumented compiler and a fresh external directory.
[Toolchain setup](../../docs/toolchain.md)

```sh
zig build counter-regenerate -- \
  --toolchain /path/to/toolchain/report.json \
  --output /tmp/counter-evidence \
  --check
```

This recaptures all four programs, compares the ordinary and captured
objects, checks the retained source hashes and programs, and replays the
success and failure proofs on fresh definitions. The directory contains logs,
manifests, a hash inventory, and `evidence.tar`.

For an intentional source change, omit `--check`, review the candidates under
`*-translation/`, and update the proof if the contract changed. Copy the
reviewed `Generated.lean` into the corresponding version directory and rerun
`zig build counter`. For manual capture, select root `counter.advance` and
the matching namespace `Compiler.Tutorial.Counter.V1.Generated`,
`V2.Generated`, `Broken.Generated`, or `Wide.Generated` under that prefix.
[Capture and translate](../../docs/native-tooling.md#capture-and-translate)

The four retained models were generated by zig2lean, now Zean, from
instrumented Zig 0.17.1 AIR on AArch64 macOS with LLVM. Lean 4.35.0 checks
the stated contracts in the scalar model. Exporter and native compiler
claims need their own evidence. [Evidence scope](../../docs/evidence.md)
